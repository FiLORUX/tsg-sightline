# Rig graphics and venue context

Schematic glyphs use an original, consistently normalised SVG plan-view vocabulary. They are not a certified EBU symbol set or measured equipment footprints. Support, payload, lens class, orientation, RF/alternative identification and metre-scale motion envelopes are independent. All legend glyphs have bounded dimensions; the full crane reach remains in the physical layer.

Legacy fragment links contain coordinates and metadata, not private venue drawings. The application now explicitly identifies missing context, and never invents an optical reference distance. A local complete project remains the fallback. An optional private resolver uses SHA-256 of the exact fragment payload after #plan=, requesting ./context/<digest>.json. It validates production, venue, revision, canvas and px/m before attaching the authorised embedded raster without replacing camera positions or falsely confirming scale. Private storage, signed authentication and project-specific permissions must be configured before enabling the resolver; never put customer assets into public static assets. Native CAD conversion, registered 3D assets and verified throws remain separate tasks.

## Deployment configuration (private)

Bind a private R2 bucket as `SIGHTLINE_CONTEXTS`. Configure the Access application on the exact canonical path `/sightline/context/*` and set `SIGHTLINE_ACCESS_ISSUER` (HTTPS Cloudflare Access team domain) and `SIGHTLINE_ACCESS_AUD` (application audience). Forward the signed `CF-Access-Jwt-Assertion` header from the canonical proxy to the existing origin. The origin independently verifies RS256 signatures, issuer, audience, expiry and per-object email ACL; the digest and proxy header alone grant no access. The R2 key is `context/<SHA-256 of exact fragment payload>.json`; custom metadata `readers` is a JSON array of approved individual email addresses. Store only the minimum overlay fields (format, meta, content, pxPerMetre, background) from the authorised source. Do not set a public bucket domain, r2.dev access, or a public static copy. Test anonymous, forged assertion, permitted and denied accounts; verify no-store and no indexing. Leave disabled if the production authorisation cannot be established.

## Authorised revision migration

A distributed link freezes one revision: its frame, its scale and its title block. When a later revision of the drawing exists, the private record (`format: sightline-context/2`) carries it together with `migration.from` and `migration.to`. The viewer applies the record only if `from` matches the link's exact revision string, frame and scale, and `to` matches the later project; any other combination fails closed and leaves the link untouched. The later revision's positions are authoritative. The viewer reports the largest shift after a best-fit similarity transform, so the change is never silent, and the scale stays an estimate until someone confirms it against a checked dimension.

Build the record with `node tools/build-context-record.mjs <link> <later-project.json> <out-dir> --scale <px/m> --chains <n> --positions <n>`. It validates identity, scale, chain and position counts, and the 24 MiB origin limit, and writes `<digest>.json`. The output belongs in the private bucket, never in this repository.

The per-object reader list is the `readers` custom metadata of the R2 object and must contain exactly the addresses permitted by the Cloudflare Access application. Neither list is stored in this repository.

## Mobile viewing and production access

The plan owns its two-contact gestures and provides explicit zoom controls and a plan-only workspace. The compact mobile context notice occupies a separate row. The authorised sign-in link returns an HTML status page rather than raw venue JSON, and the original tab retries when focus returns. Google Drive and Cloudflare Access authorisation are separate. A release must verify the actual distributed link in an approved account, including R04 background, scale, 15 chains/16 positions and optical coverage. Anonymous, denied and forged credentials must not return the private record. Touch-enabled Chromium is a regression gate; real iOS Safari acceptance and the actual live Access policy remain separate production checks.
